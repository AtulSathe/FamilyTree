Zustand Stores (src/store/)

treeStore.ts — React Flow controlled mode with layout algorithm NEW
Design decision: Uses React Flow "controlled mode" (nodes + onNodesChange) rather than uncontrolled. This lets Zustand be the single source of truth for the canvas state.

Layout algorithm (no external dependency)

const H_GAP = 220, V_GAP = 180

// Given a focal person at (cx, cy):
// - Parents placed above at cy - V_GAP, horizontally centred
// - Children placed below at cy + V_GAP, horizontally centred
// - Spouses placed right: cx + H_GAP*(i+1), cy
// - Siblings placed left:  cx - H_GAP*(i+1), cy

// Edge colours:
// parent_of (smoothstep): #10b981 (green)
// spouse    (straight, dashed): #f59e0b (amber)
// sibling_of (straight, dashed): #8b5cf6 (purple)

Hooks (src/hooks/)

usePersonSearch.ts — 350 ms debounce NEW 
export function usePersonSearch(surname?: string) {
  const [query, setQuery] = useState('')
  const [debouncedQ, setDebouncedQ] = useState('')

  useEffect(() => {
    const t = setTimeout(() => setDebouncedQ(query), 350)
    return () => clearTimeout(t)
  }, [query])

  const { data: results = [], isFetching } = useSearch(debouncedQ, surname)
  return { query, setQuery, results, isFetching }
}

Design Decisions

Why no dagre / elkjs for layout?

dagre is officially deprecated and has no @types. elkjs requires WebAssembly and adds ~1 MB to the bundle. The family tree layout is simple enough (parents above, children below, spouses right, siblings left) that a manual 15-line algorithm handles it correctly. More complex layouts can be added later if needed.

Why controlled React Flow mode?

React Flow v12 recommends controlled mode when external state management is used. This ensures Zustand is the single source of truth — the tree canvas can be updated from any component (LeftPane click, search result click, expand button) without prop drilling.

Why PersonNodeData extends Record<string, unknown>?

React Flow v12 requires node data to be indexable. The extends Record<string, unknown> constraint satisfies this at the type level without using any.

Why onMouseDown on SearchResult items?

The SearchBar input has onBlur={() => setTimeout(() => setOpen(false), 150)}. When a user clicks a result, onBlur fires first (before the click event). Using onMouseDown fires before blur, allowing the navigation to happen before the dropdown closes.

Auth mock default — family_admin for Sathe tree

The default mock user matches seed user ID 00000000-...0002 (Ramesh Sathe) with family_admin role and assignedTrees = [Sathe tree ID]. This makes the default MSW experience realistic: Edit buttons appear on Sathe persons, are hidden on Panse persons, and community_member role can be set by modifying authStore.user.
