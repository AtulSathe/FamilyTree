cosmos.bicep — Cosmos DB Gremlin

Cosmos DB account + Gremlin database + graph BICEP
Free tier (dev): When enableFreeTier: true, Cosmos DB gives 1000 RU/s and 25GB storage free — sufficient for dev/test. Only one free-tier account per subscription.

Resources created

  • Microsoft.DocumentDB/databaseAccounts — kind: GlobalDocumentDB, capability: EnableGremlin
  • Microsoft.DocumentDB/databaseAccounts/gremlinDatabases — familytree, 400 RU (prod)
  • Microsoft.DocumentDB/databaseAccounts/gremlinDatabases/graphs — relationships, partitioned by /primaryTreeId

Partition key rationale

/primaryTreeId is chosen because the most common graph traversals (expand node, find neighbours) stay within a single family tree. Cross-tree queries (surname relationship detection) are infrequent background jobs that tolerate cross-partition reads.

Outputs → App Settings mapping

cosmos.outputs.gremlinEndpoint  → CosmosDb__GremlinEndpoint  (e.g. familytree-cosmos-prod.gremlin.cosmos.azure.com)
cosmos.outputs.gremlinPort      → CosmosDb__GremlinPort       (443)
cosmos.outputs.gremlinUsername  → CosmosDb__GremlinUsername    (/dbs/familytree/colls/relationships)
cosmos.outputs.primaryKey       → CosmosDb__GremlinPassword    (@secure)

storage.bicep — Blob Storage + CDN

Storage account + person-photos container + CDN endpoint with 24h cache BICEP
CORS configuration: Allows PUT from any origin — required for the SAS token direct-upload flow (browser PUT directly to Blob). Restricting to the SWA origin is recommended for production hardening.

Resources created

  • Microsoft.Storage/storageAccounts/blobServices — CORS for GET/PUT/OPTIONS
  • Microsoft.Storage/storageAccounts/blobServices/containers — person-photos, public blob access
  • Microsoft.Cdn/profiles — Standard_Microsoft
  • Microsoft.Cdn/profiles/endpoints — HTTPS only, 24h cache for image/* content types

Photo upload flow (CLAUDE.md §Photo upload)

1. Client → POST /persons/{id}/photo-upload-url → { sasUrl, blobName }
2. Client → PUT sasUrl (file bytes directly, no API bandwidth)
3. Client → PUT /persons/{id} { photoBlobUrl: cdnBaseUrl + '/' + blobName }
4. API saves CDN URL to SQL + Cosmos vertex property

Design Decisions

Why Standard_Microsoft CDN (classic) instead of Azure Front Door?

Azure Front Door Standard/Premium is the modern recommendation but costs ~$35/month minimum. For a family tree app with modest photo traffic, Standard_Microsoft CDN (classic) at ~$0.087/GB outbound is sufficient. Migration to Front Door is straightforward later (same Blob origin).

Why partition Gremlin graph by /primaryTreeId?

The vast majority of Gremlin traversals (expand node, get neighbours) stay within a single family tree. Partitioning by primaryTreeId keeps those queries within one physical partition, avoiding cross-partition fan-out and reducing RU costs. Cross-tree queries (surname link detection) are run by the background job on a timer and can tolerate the slightly higher RU cost of cross-partition reads.

Why split build and deploy into two CI jobs?

Splitting into two jobs means: (1) PRs run the build+test job but not the deploy job — saves deployment quota and avoids accidental deploys; (2) test results are uploaded as an artifact even when the build fails; (3) the deploy job has its own environment: production gate which can require a manual approval review in GitHub.

Why skip_app_build: true in the SWA deploy action?

Azure Static Web Apps deploy action uses Oryx to build the app by default. Oryx doesn't have access to our GitHub Secrets for VITE_* env vars, so a remote build would create a bundle with empty strings for all config. By building ourselves in the previous job (where secrets are available) and uploading dist/, then using skip_app_build: true, we guarantee the production config is baked into the bundle.

Why is allowedOrigin empty on the first deploy?

The SWA hostname isn't known until after the first deploy creates the resource. The two-pass approach (deploy → capture URL → redeploy with CORS) is the standard Bicep pattern for circular dependency between resources. An alternative is to use a custom domain with a known hostname, which eliminates the two-pass requirement.
